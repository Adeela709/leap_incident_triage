I chose TF-IDF with Logistic Regression as my baseline model. I chose it because it was simple enough for me to understand and explain, while also being lightweight and suitable for the relatively small text dataset. The final model file was only 7,951 bytes. I considered using a more complex model, but I decided that would add complexity without me being confident that I could explain or deploy it properly within the assessment time.
I removed incident reports with unusable descriptions. There were 85 rows with missing or unusable descriptions such as -, TBC, or see attached report, so I excluded them from the text model and worked with 1,360 usable incidents. I decided this was better than inventing or guessing missing descriptions. I considered keeping them, but they would not give the text model meaningful information.
I fitted TF-IDF only on the training data. I used fit_transform() on the training descriptions and transform() on the test descriptions. I chose this because I wanted the test data to remain unseen during training and evaluation. I considered fitting TF-IDF on all the data, but rejected it because it would allow information from the test set into the preprocessing stage.
I used an 80/20 train-test split to evaluate the model. This gave me 1,088 training incidents and 272 test incidents. I used random_state=42 so that I could reproduce the same split while developing. I considered using a more complicated validation strategy, but chose the simple held-out test set because I was working with limited time and wanted an evaluation process I could understand and reproduce.
I kept the baseline model rather than trying to optimise the HIGH-severity recall further. The model achieved 83.46% accuracy, but HIGH-severity recall was only 0.33, so the model missed some incidents labelled HIGH. I recognised that this is important because the HSE Manager specifically wants serious incidents identified quickly. I did not make further model changes because I was still learning the modelling and deployment process and did not want to make changes that I could not properly explain or validate. A more advanced approach such as changing class weights, decision thresholds, or comparing additional models would need further testing to show that it improved HIGH-severity detection without creating excessive alerts for the Shift Supervisor.
